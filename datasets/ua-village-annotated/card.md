# ua-village-annotated — dataset card

> Equipment, not an experiment. Written by hand; `manifest.json` alongside it
> is generated by the first real export (`python -m tools.annotator export`)
> and holds the numbers. **Status: recipe ready, no samples yet** — nothing has
> been annotated.

## What this is

Hand-corrected six-class segmentation labels over the imagery of
`ua-village-multidate`. A **sample** is one location on one date. Labels start
from machine reference sources (OSM, Microsoft footprints, LandCover.ai, FLAIR,
ESA WorldCover), each seeded into its own editable sublayer, and are fixed by
hand in `tools/annotator/` until a person marks that date `done`. Only `done`
samples are exported.

| id | class | seeded from |
|---|---|---|
| 0 | background | — |
| 1 | building | osm, ms-footprints |
| 2 | track (paved + unpaved) | landcoverai, osm (centrelines with width) |
| 3 | woody (wood mass + treelines) | osm, landcoverai, worldcover, flair |
| 4 | field | nothing — drawn by hand |
| 5 | water | osm |

Overlaps are kept while editing; export resolves them by priority
`building > track > water > woody > field > background`.

## How it was built

1. `python -m tools.annotator.refs run --source all --locations all` writes
   one reference per (source, location) on the `current` date.
2. The annotator seeds a workspace per location on first open; a person
   corrects it: base annotation shared by all dates, plus per-date overrides
   (add / remove) where the ground changed.
3. `python -m tools.annotator export --new|--stale|--all` composes each date
   (base − remove + add, vectors rasterized, sublayers unioned, priority
   applied) and writes the label plus a record in `samples.jsonl`.

Images are **not copied**: each record's `image_file` points into
`ua-village-multidate`.

### Extending

`samples.jsonl` holds, per sample, the `annotation_hash` (content of every
layer that decides that date's label), `classes_version`, the reference
sources and versions behind each sublayer, per-class provenance, and the
georeference. `--new` exports only what has no record; `--stale` re-exports
records whose hash or class registry changed. Adding a class bumps
`classes_version` in `tools/annotator/classes.json`, which flags every existing
sample as needing review for it.

## Known problems

- **Labels are as good as the person who approved them.** There is no second
  annotator and no agreement measure yet.
- Reference seeds carry their known biases into anything left uncorrected:
  LandCover.ai over-claims water on ploughed fields and track ~3×; FLAIR is
  date-inconsistent (44–57% self-agreement); WorldCover is a 10 m staircase.
  `provenance` in each record says how much of a class came from which source.
- **MS footprints have no coverage at 5 locations** (brailivka, hermakivka,
  nehrovets, neporotove, ploske): the quadkey files download fine but hold no
  footprint within 1 km. There `building` is seeded from OSM only.
- `field` has no seed; a date with no field drawn is indistinguishable from a
  date with no fields.
- OSM geometry was shifted by the measured `label_offset` only where that
  measurement was trustworthy (`peak_z ≥ 4`); elsewhere it is as mapped.

## What this is NOT valid for

Same scope as `ua-village-multidate`: rural west/centre Ukraine, Esri imagery,
nadir. It says nothing about drone-frame appearance.
